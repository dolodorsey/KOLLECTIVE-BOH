# Entity 110% Certification Standard

**Effective:** 2026-09-30  
**Canonical state:** Supabase KOLLECTIVE BOH `wfkohcwxxsrhcxhepfql`

An entity is not complete because it has a logo, site, social account, CRM record or campaign. “110% developed” means every applicable operating layer has canonical data, an execution route, and a proof standard.

## 1. Identity + Governance
- canonical entity key/name/division/status
- brand isolation boundaries
- operating packet / Brand Intelligence Packet
- runtime ownership
- current priorities and restricted actions

## 2. Brand + Offer
- audience
- positioning
- voice and avoid-list
- approved products/services/offers
- pricing/CTA/destination
- approved claims/evidence
- asset source

## 3. Social
- account mapping
- cadence
- post-goal taxonomy
- caption law
- Story/Reel/Carousel/Collab standards
- publishing route
- native receipt/permalink
- engagement law

## 4. Email + Lifecycle
- entity sender
- provider route
- eligible audience + suppression
- daily cadence
- message rotation
- conversion destination
- provider receipt/deliverability evidence
- follow-up sequence

## 5. PR + Authority
- readiness packet
- evidence library
- active story angles
- outlet/contact targets
- pitch/follow-up queue
- placement/amplification proof

## 6. Ambassador + Influencer
- applicability decision
- program/archetypes
- approved perks/terms
- qualification/scoring
- outreach
- onboarding
- code/link only after acceptance
- deliverables/attribution/performance

## 7. Sales + Revenue
- offer + target definition
- pipeline
- warm relationship priority
- outreach/follow-up rules
- next-action discipline
- meeting/proposal/close path
- won/lost reason
- revenue/attribution proof

## 8. Daily Operating Rhythm
- morning priority
- midday execution
- afternoon recovery
- EOD closeout
- provider receipts
- exact blockers
- tomorrow's top three

## 9. Tech + Data
- web/app destination
- CRM/entity mapping
- Supabase source of truth
- provider credentials/routes
- dashboard visibility
- logging/health monitoring
- failure/backup path

## 10. Compliance + Security
- age/regulatory controls where applicable
- DND/consent/suppression
- restricted claims/topics
- least-privilege access
- RLS/policy review
- no client-side secrets

## 11. Reporting + QA
- business KPIs
- channel KPIs
- sales KPIs
- daily receipts
- failed-action reasons
- regression protection
- founder decisions separated from routine execution

## Certification states
- **PASS:** every applicable layer has canonical data + execution route + proof.
- **SETUP REQUIRED:** entity remains active; the gap automatically becomes operating work.
- **NOT APPLICABLE:** explicit and evidence-backed. Silence is never N/A.
- **BLOCKED:** exact blocker, owner/runtime and next action are recorded.

Do not call an entity “complete” while required sections are setup-required, blocked, missing proof, or relying on an unverified provider route.
