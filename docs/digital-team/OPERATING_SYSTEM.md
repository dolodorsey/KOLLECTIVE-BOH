# Digital Team Operating System — Marketing + Sales

**Effective:** 2026-09-30  
**Canonical data:** Supabase KOLLECTIVE BOH `wfkohcwxxsrhcxhepfql`  
**Repository role:** Human-readable/versioned mirror only. Supabase state wins for live records and receipts.

## Rule hierarchy
1. Current founder directive/correction
2. KOLLECTIVE DOT OS Constitution
3. Lane Task Master / SOP
4. Entity Brand Intelligence Packet
5. Current campaign/event/product brief
6. Daily work order
7. Native provider receipt/result

## Who owns what
- **DOTs:** strategy, lane governance, prioritization, task selection.
- **Muse:** provider execution when the connected provider actually supports the action.
- **ChatGPT:** architecture, QA, audits, correction, cross-system orchestration.
- **Claude:** scoped code/repo implementation and technical verification; never a duplicate external sender.
- **GHL:** CRM/lifecycle/campaign execution only when entity mapping, sender and live permissions are verified.
- **Supabase:** canonical operating state, packets, queues, receipts, metrics.
- **Vercel:** runtime/deployment surface for dashboards/sites/apps; READY/deployed is not business completion.

## No-human-team law
Do not create a process that assumes a human operator exists. Execute authorized reversible work with the connected agent/tool. Escalate only founder-reserved decisions, real credential/permission blockers, binding legal/financial commitments, destructive actions or provider limitations.

## Brand isolation
Every entity keeps its own identity, voice, assets, sender, audience, CRM lane, offer, social account, attribution, reporting and receipts. Cross-brand collaboration is explicit; identity is never merged.

## Daily priority
1. Revenue/replies/inbound intent
2. Follow-up and closing
3. Daily email/lifecycle
4. Social publishing + stories + engagement
5. PR/authority
6. Ambassador/influencer recruiting + activation
7. Qualified outbound
8. Content replenishment, lead sourcing and retargeting when those phases are activated

## Definition of done
Queued != sent. Scheduled != posted. READY != live. Deployed != accepted. Attempted != delivered. A provider/native receipt is required whenever available.
