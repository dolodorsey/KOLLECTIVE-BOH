# Multi-Agent Daily Command Schedule v1

**Canonical source of truth:** KOLLECTIVE BOH Supabase `enterprise_prompt_os_documents.multi_agent_daily_command_schedule_v1`  
**Effective:** 2026-10-01  
**Timezone:** America/New_York

This GitHub file is an implementation mirror. Supabase controls current schedule/state.

## Roles

- **DOT:** strategy, priority, revenue selection, task claiming, specialist routing.
- **Muse:** supported external/provider execution with exact account identity and native receipts.
- **Claude:** scoped technical repair, testing, deployment/runtime reliability, desktop/mobile QA. No duplicate customer sends.
- **ChatGPT:** control tower, cross-system QA, receipt/claims verification, analytics, blocker detection and founder closeout.

## Daily command window

| Time ET | Phase | Required outcome |
|---|---|---|
| 05:00 | Day Open / Overnight Reconciliation | Verified starting state, priorities, blockers, owner per action |
| 06:00 | Readiness + Repair | Repaired / ready / blocked state with evidence |
| 07:00 | Execution Packaging | One-writer executable queue with proof requirements |
| 08:00 | Morning Command | Objective, revenue gap, top actions and blockers by focus entity |
| 09:00 | First Revenue / Execution Block | Actual sends/posts/replies/applications/meetings/cash/stage movement |
| 10:00 | Mid-Morning Proof Check | EXECUTED / BLOCKED / NO_WORK with evidence |
| 11:00 | Morning Handoff | Canonical handoff into the daytime operating window |

## Periodic execution checks

- **13:00 ET — Midday Proof Pulse:** verify native receipts, replies, pipeline, content/email state and revenue; recover missed work once.
- **16:30 ET — Recovery Check:** move the highest-value unresolved opportunity or repair the conversion blocker.
- **20:00 ET — Daily Closeout:** reconcile cash, pipeline, provider receipts, sends/posts, obligations, failures and tomorrow's top three actions.

## Execution laws

1. One action has one active writer.
2. Provider/production evidence outranks agent narrative.
3. No receipt means not executed; unknown remains unknown.
4. Keep every brand/entity isolated by sender, account, audience, CRM location, assets, data, offer and reporting.
5. Preserve current holds and approval/compliance gates.
6. Do not reactivate legacy focus automations through this schedule.
7. Supabase is scheduler/task/receipt truth; GitHub and Vercel are engineering/deployment evidence surfaces.
8. Direct ChatGPT HighLevel connector IAM state does not by itself determine provider availability; use the approved exact-location Supabase runtime architecture.

## Handoff standard

Every handoff must include: entity key, objective, exact account/repo/project, current verified state, active owner, allowed write surface, last receipt, blocker, next action, acceptance criteria and proof required.
